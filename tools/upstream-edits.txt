source/appModuleHandler.py
  process identity: on Linux the application name, executable path,
  architecture, user and liveness of a process come from /proc and a pidfd
  through linuxPlatform.processes, not from Toolhelp, a process handle,
  IsWow64Process2 or the logon session. processHandle is None, so
  getAppModuleForNVDAObject never asks a window for one; product name and
  version raise NoLinuxImplementation; a Windows app module that fails to
  import while a name is looked up is reported by fetchAppModule instead
source/argsParsing.py
  Linux: help goes to standard output and a command-line error to standard
  error with exit status 2, as argparse does, instead of a Windows message
  box
source/audio/soundSplit.py
  sound split, workstream A5: Linux has no counterpart yet of Windows' audio
  session manager, through which sound split sets other applications'
  volumes. On Linux initialize() leaves it unset instead of calling pycaw,
  which core.main would not survive; the toggle script says "Sound split
  not supported"; setting the state to off has nothing to restore, and any
  other state raises NoLinuxImplementation

source/keyboardHandler.py
  Linux runtime: what a key press needs from the live keyboard comes from
  linuxPlatform.inputHook, where a capture layer will answer it: the sticky
  keys flags, whether num lock is on for a numpad operator key, and the
  character that names a key with no name of its own. A single character in
  a key name is looked up there too, which answers for lower case letters
  without the layout. Until a capture layer exists the rest raise
  NoLinuxImplementation
source/languageHandler.py
  Linux: the interface language, the C locale, language names and the
  measurement system come from linuxPlatform.posixLocale, which reads the
  POSIX environment, instead of from Windows locale calls. getWindowsLanguage
  reports the first language LANGUAGE lists that NVDA has a translation for,
  and otherwise the user's own language whether translated or not, as
  Windows reports its display language. Converting a name
  to a Windows locale identifier gives LCID_NONE and the reverse uses
  Python's table. The catalogue directory is absolute under appDir on every
  platform, so translations no longer depend on the working directory
source/logHandler.py
  running on Linux: the time comes from logging's own formatTime, not Win32
  time conversion; log.exception reads comtypes only on Windows; NVDA's own
  modules are told from external code with the platform's path separator,
  which on Windows is the backslash upstream wrote; a record that cannot be
  written is reported on the real standard error, since sys.stderr is
  redirected into the log and the report would fail again without end; the
  default log is under XDG_STATE_HOME/basedreader; log files are created
  readable by the user alone, since the log can record every key typed; the
  error sound is requested from a thread of its own, which stops it when
  errors keep following it, and CRITICAL has no sound, not the winsound
  beep; faulthandler is armed with a crash file beside the log once the
  log's handler is installed, so that a failure to arm it is logged.
  The Linux code is in linuxPlatform/logSupport.py

source/synthDriverHandler.py
  synthesizer selection on Linux: getSynthList skips NVDA's own copies of
  the Windows-only driver modules (mssp, oneCore, sapi4_32, sapi5,
  sapi5_32), which cannot import and would each log an error, but not an

  checks that the skipped set is exactly the set that fails to import

source/systemUtils.py
  import safety: winreg imported only on Windows, after the module's other
  imports. Linux: hasUiAccess() is True, as X11 isolates no client from
  another; Wayland sessions are not handled. Its consumers then do this:
  gui's MainFrame skips the Show and Hide trick, which is wanted; the
  full-screen magnifier believes input transforms are supported; touch and
  audio ducking still answer unsupported, through isInstalledCopy(); the
  remote client's _canSendSAS goes on to winreg, which is absent, so a
  remote control+alt+delete raises NameError; and _isObjectBelowLockScreen
  goes on to Win32 z-order calls, which fail through the stand-ins once lock
  tracking exists. hasSyswow64Dir() and _isSystemClockSecondsVisible() are
  False; the configuration directory opens through xdg-open;
  preventSystemIdle() warns once that the session may still go idle and
  returns, as say all and braille keys call it, and
  resetThreadExecutionState() has nothing to release. ExecAndPump waits for
  its thread while yielding to the wx main loop instead of pumping Windows
  messages. The process token, logon session, elevation and desktop name
  functions still fail on Linux through the Windows stand-ins
